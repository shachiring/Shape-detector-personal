1. PROJECT OVERVIEW
--------------------------------------------------------------------------------

The Geometric Shape Detector is a client-side computer vision application built
from the ground up without relying on external computer vision libraries such as
OpenCV, TensorFlow, or Python backends.

The primary objective of this project is to take raw image pixel data (via
HTML5 Canvas ImageData), detect any 2D geometric shapes present in the scene,
localize their exact positions and bounding boxes, and classify each shape into
one of five fundamental geometric categories:
  1. Circles
  2. Triangles
  3. Rectangles / Squares
  4. Pentagons
  5. Five-Pointed Stars

The application features:
  - Real-time shape detection with sub-20ms execution times per image.
  - Interactive web UI allowing users to click pre-loaded test images or
    upload custom images/screenshots.
  - Dynamic visual overlays drawing emerald bounding boxes, centroid coordinates,
    and confidence badges directly onto the image canvas.
  - A rigorous automated evaluation suite benchmarking precision, recall,
    F1-score, and Intersection over Union (IoU) against ground truth data.

2. CORE ARCHITECTURE & THE 5-STAGE COMPUTER VISION PIPELINE
--------------------------------------------------------------------------------

The engine operates on pure pixel manipulation using a modular 5-stage pipeline:

STAGE 1: ADAPTIVE BINARIZATION & AUTO-POLARITY DETECTION
  - Raw RGBA pixel buffers are converted to grayscale using standard luminance
    weighting: Gray = 0.299*R + 0.587*G + 0.114*B.
  - To support diverse image types (light-on-dark, dark-on-light, or transparent
    PNGs), the algorithm samples perimeter boundary pixels to calculate the
    mean background luminance.
  - If the background is dark (mean < 90), foreground shapes are segmented by
    identifying brighter pixels; otherwise, dark pixels on a light background
    are selected.
  - The result is a clean 2D boolean grid marking foreground shape pixels.

STAGE 2: CONNECTED COMPONENT LABELING (CCL) VIA BFS
  - Breadth-First Search (BFS) flood fill groups contiguous foreground pixels
    into discrete components ("blobs").
  - An adaptive minimum pixel area threshold filters out single-pixel noise,
    speckles, and stray artifacts without dropping small valid shapes.

STAGE 3: TRUE MOORE-NEIGHBOR CONTOUR TRACING
  - For each detected blob, the algorithm identifies the top-most, left-most pixel.
  - It traverses the outer boundary using the Moore-Neighbor Tracing algorithm
    with background backtracking:
      * Searches clockwise starting from the last known exterior background neighbor.
      * Ensures boundary points remain on the outer edge and never cut into the
        interior of polygons or corners.
      * Applies Jacob's stopping criterion (terminates only when returning to the
        starting pixel via the exact original entry vector) to ensure complete
        closure of complex polygons.

STAGE 4: POLYGONAL SIMPLIFICATION (RAMER-DOUGLAS-PEUCKER)
  - The raw boundary pixel sequence (often 200–500 points) is simplified using the
    Ramer-Douglas-Peucker (RDP) algorithm across adaptive epsilon scales.
  - This reduces the contour into dominant geometric vertices while eliminating
    pixel staircase artifacts.

STAGE 5: MULTI-METRIC GEOMETRIC CLASSIFICATION & LOCALIZATION
  - Shape classification is evaluated using a hierarchical decision tree:
    1. Star: Identified by 9–12 simplified vertices exhibiting an alternating
       near/far radial distance pattern relative to the centroid (ratio >= 0.60).
    2. Triangle: Simplified to exactly 3 dominant vertices.
    3. Rectangle / Square: Simplified to 4 dominant vertices (handles arbitrary
       rotation angles).
    4. Pentagon: Simplified to 5 dominant vertices.
    5. Circle: High circularity index: 4 * PI * Area / (Perimeter^2) > 0.78,
       coupled with smooth non-polygonal curvature.
  - Once classified, the engine calculates:
    * Bounding Box: [minX, minY, width, height]
    * Centroid: Center of mass / polygon centroid
    * Area: Geometric formula (Pi * r^2 for circles, shoelace formula /
      bb area for polygons)
    * Confidence Score: Calibrated probability percentage (80% - 98%)

3. CHALLENGES ENCOUNTERED & HOW WE SOLVED THEM
--------------------------------------------------------------------------------

During development and testing, several critical bugs were encountered and
systematically resolved:

1. THE CONTOUR TRACING CORNER-CUTTING BUG:
   - Problem: The initial contour tracing implementation used an incorrect
     search offset direction. When encountering 90-degree corners or polygon
     vertices (rectangles, pentagons, squares), the tracer took an immediate
     diagonal shortcut into the corner interior, creating a tiny 5-pixel loop
     and prematurely terminating. Consequently, rectangles and pentagons
     were filtered out with "0 shapes detected".
   - Solution: Replaced the directional heuristic with a mathematically robust
     Moore-Neighbor tracer that tracks the exterior background pixel coordinate
     frame and terminates only on Jacob's stopping criterion. This restored
     full 360-degree boundary tracing for all geometric shapes.

2. SQUARE VS. CIRCLE CIRCULARITY COLLISION:
   - Problem: A square has an exact theoretical circularity of Pi / 4 (~0.785).
     An earlier heuristic checked "if circularity > 0.75 then Circle" before
     evaluating vertex count, causing perfect squares to be misclassified as
     circles.
   - Solution: Reordered the classification priority so that vertex-based
     polygon detection (3 for triangle, 4 for rectangle, 5 for pentagon) takes
     precedence over circularity thresholds.

3. SENSITIVITY TO IMAGE INVERSION & BACKGROUND LIGHTING:
   - Problem: Hardcoded thresholding (gray < 128) failed on screenshots with
     dark backgrounds (dark mode IDEs, circuit schematics, graphs).
   - Solution: Implemented automatic border-pixel luminance sampling to detect
     background polarity and dynamically adjust the binarization logic.

4. MISSING BENCHMARK ASSET IN PUBLIC FOLDER:
   - Problem: The automated evaluation suite expected "ground_truth.json" to be
     served statically at "/ground_truth.json", but it was only located in the
     project root. This caused fetch requests during evaluation to fail.
   - Solution: Copied and synced "ground_truth.json" into "public/ground_truth.json".

5. LACK OF VISUAL CANVAS FEEDBACK:
   - Problem: The original UI only rendered text results in an HTML sidebar
     without indicating where the shapes were detected on the canvas.
   - Solution: Implemented a dedicated "drawDetections()" method that paints
     vibrant emerald green bounding boxes, solid red centroid dots, and
     prominent badge tags (e.g., "RECTANGLE 95%") directly over the canvas.

5. HOW TO RUN AND TEST THE PROJECT
--------------------------------------------------------------------------------

1. Install Dependencies:
     npm install

2. Start the Local Development Server:
     npm run dev
     (Open http://localhost:5174 in your browser)

3. Production Build:
     npm run build

4. Using the Web Interface:
   - Click any shape thumbnail at the bottom to test instant detection.
   - Click "Select All" and "Run Selected Evaluation" to view the full
     benchmark report modal.
   - Click the "Upload Image" tile to test custom screenshots or images.
